# IA — Session state

**Purpose:** Current implementation snapshot for handoff. Architecture and engineering conventions live in [ia.md](ia.md) and product details live in [project.md](project.md).

**Updated:** 2026-10-23
**Version:** Frontend package `0.0.1`; no repository-wide release version is declared. `.python-version` selects Python `3.13.5`.

---

## Current state

- **Architecture/runtime:** Flask backend and React 18/Vite frontend. `backend/run.py` loads the repository-root `.env`. Flask serves `frontend/dist` when built, otherwise serves the frontend directory. Vite dev server uses port 5174 and proxies `/ai`, `/auth`, `/notes`, `/memories`, `/activity`, `/files`, and `/settings` to Flask at `127.0.0.1:5000`.
- **Authentication:** Registration/login store password hashes in ignored local `backend/data/users.json` and issue HS256 JWTs. Persisted roles are `user`, `admin`, or `main_admin`; `GET /auth/me` exposes the current role. JWTs carry only `sub`; unlimited credits and diagnostics viewing use `app/auth/permissions.py`. Main Admin is designated via `python -m scripts.bootstrap_main_admin` (explicit env), optional dev/test startup auto-seed (`IA_AUTO_SEED_MAIN_ADMIN` and related env), or a one-time production startup bootstrap (`IA_PRODUCTION_BOOTSTRAP_MAIN_ADMIN` and related env) when the user store and Main Admin marker are both absent; CLI bootstrap can also create the first owner when the store is empty or promote an existing account. Main Admin user list/promotion APIs exist at `/admin/users`; the authenticated SPA exposes role-gated **Users** (main_admin) and **Diagnostics** (admin and main_admin) at `/admin/users` and `/admin/diagnostics`, with role loaded from `/auth/me`. Backend authorization remains authoritative. `JWT_SECRET` is required during `create_app()` startup; it must be at least 32 characters with at least 8 distinct characters. Missing, weak, or placeholder values fail startup with a generic error. Protected routes read the user ID from `sub`; token lifetime defaults to seven days. The frontend stores the token in `localStorage` and clears it after a rejected 401.
- **AI Credits:** Per-user JSON balance, ledger, and Ask operation results are stored under ignored `backend/data/`. Defaults are 100 initial credits for newly initialized accounts and 1 per Ask. Newly registered users receive the configured initial credit balance when their credit account is first accessed. Registration does not create the credit account eagerly, so a credit-storage failure does not prevent account registration. Changing the initial-balance setting does not change an existing credit account. Ask reserves before AI work, rejects insufficient balance with 402, and refunds when AI execution raises. Completed duplicate operations return the saved result; active duplicates return 409. The process-local lock is not a multi-worker transaction. The configured unlimited role defaults to `admin`. Rewarded-ad grants are enabled only in development/test and are not provider-verified.
- **Memory:** Independent records live in `backend/data/memories_<user-hash>.json`, separate from Notes and `_history` conversations. The per-user `memory_enabled` Setting defaults to false. When enabled, Ask retrieves relevant records with lexical ranking and low-overlap AI classification (up to eight items / 180 estimated tokens), injects them as untrusted background facts, then best-effort extracts bounded user-grounded memories from user messages. Supported standalone persistent assistant-name updates and recognized standalone temporary name commands use deterministic paths; ambiguous or compound messages use one structured extraction request and validate candidates independently. Temporary assistant-name instructions do not suppress unrelated durable facts in the same message; quoted, reported, and hypothetical name instructions cannot overwrite the saved preference. Extraction failure does not fail the answer; explicit forget requests can remove matching owned records. Secret patterns are rejected. No relational database or migration is used because the repository's persistence convention is per-user JSON.
- **Ask context:** Source visibility, the `show_context_source_labels` preference (default true), and Notes context modes persist in per-user Settings; selected Note IDs are retained in per-tab `sessionStorage` keyed by JWT subject so the selected context survives Ask → Manage → Ask. The API keeps a current-session Settings cache keyed by JWT subject, invalidates it on account changes, and waits for pending writes before returning settings. Ask uses cached preferences on the first render when available and keeps its toolbar hidden while preferences are unknown. Note content remains in the existing per-user Notes store and the IDs are sent only when Notes mode is enabled. Memory is an ON/OFF setting persisted in per-user Settings; it controls both automatic extraction and retrieval. Its mode is not client-authoritative: the AI route reads `memory_enabled` from server-side settings for the authenticated JWT subject. Memory and Notes do not share context composition. Conversation opens the existing history selector and continues through its separate `messages` flow. Conversation, Notes, and Memory are visible by default. Files has no Ask context flow; GitHub, Drive, and Web remain placeholders and do not retrieve context.
- **Conversation history:** Conversations are per-user notes with category `_history`. Ask sends up to 30 prior turns to the AI provider and saves the next user/assistant pair through `PUT /notes/<id>`. Because the page switch unmounts Ask, its active note ID is saved in per-tab `sessionStorage` scoped by the authenticated JWT subject. On remount, Ask reloads the current title and messages using the existing Notes API. A newly selected/created conversation replaces the ID; logout clears it, and a missing or non-history note safely clears the stale selection. Only the active ID is persisted: drafts, selected note IDs, and scroll position remain transient; Notes context preferences continue to use per-user Settings.
- **Ask focus and messages:** The separate Focus control hides the app header and Ask context shortcuts while retaining history, the question textarea, and Ask button. AI responses have per-message Copy controls that copy plain text with line breaks and list structure preserved. Only user turns are editable; edit/resend replaces that turn and later turns through the existing Ask and note-update flow.
- **Manage:** The authenticated `/manage` page organizes Notes and Conversations by reusing their existing interfaces. Its Memory section loads persisted user records from authenticated `/memories/` APIs, shows the ON/OFF setting, and supports editing, deleting, and confirmation-protected clearing. Note creation and image import remain available in Manage, not in the Ask Notes selector.
- **Notes:** Per-user JSON CRUD, category/tag filters, and image import using OCR plus AI summary. Image imports with a matching title/category append to that note.
- **AI Suggestions:** Successful non-history Note and flashcard-deck create/update/delete operations record fixed descriptions and timestamps as internal suggestion context in a separate hashed per-user JSON file. The authenticated `/activity/` API returns up to 100 newest events (50 by default) for the overlay. The default-on per-user `ai_suggestions_enabled` preference gates the dismissible suggestion overlay; after at least two tracked actions in seven days, the configured AI receives only fixed event-type counts and chooses a supported action. No Note content is provided. Dismissals are keyed to the authenticated user in local storage.
- **Runtime data/deployment:** `backend/data/` holds local user, internal suggestion-event, and generated AI-memory artifacts and is ignored by Git. `backend/run.py` loads the repository-root `.env`, creates the Flask app, and runs the Flask development server when executed directly. JSON stores use process-local `threading` locks in managers (`users.json`, credits, diagnostics); the Main Admin marker uses exclusive create only on first write. That model supports **one backend process** and **one local data directory** per deployment; it is **not** safe for multiple workers or multiple instances sharing the same directory, including on a network volume. See [project.md — JSON storage and deployment limits](project.md#json-storage-and-deployment-limits). The repository does not include `gunicorn.conf.py` or cross-process file locking. `frontend/public/_redirects` provides a static-host SPA fallback. Deployment values remain external and no provider-specific backend deployment manifest, shared-volume type, or hostname is declared in tracked files.

For backup or restore, stop the backend and copy/restore the entire `backend/data/` directory; keep backups encrypted and access-controlled, and protect `.env` secrets separately. The repository does not configure or verify persistent production volumes, backup schedules, or a production restore procedure.

## Seed safety

`backend/scripts/seed_user.py` is restricted to `APP_ENV=development` or `APP_ENV=test`. Production demo seeding uses the separate, explicitly enabled `backend/scripts/seed_render_demo.py` command and a password-manager-generated password provided through protected environment configuration. It refuses to adopt an existing `demo` account unless its instance-local marker matches the stored user ID; the marker is ephemeral on Render Free. Neither seeder changes an existing account's password, role, settings, or credit balance. Never commit local credentials.

## Current verification surface

- Backend checks are documented in [testing.md](testing.md), including compilation, suggestion-event and AI Suggestions authentication/isolation/action tests, AI/context/credit tests, seed idempotence, and settings persistence.
- Frontend verification includes the Vitest/jsdom App/Ask and AI Suggestions regressions and existing Node source-mode tests (`npm --prefix .\frontend test`), the Vite production build, and manual UI regression. Component tests mock Notes, suggestion-event, and AI HTTP responses and do not require a live provider.
